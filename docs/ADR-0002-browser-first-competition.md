# ADR-0002：以在线可交互作品为主，保留单一 Python 规则内核
日期：2026-11-03　状态：ACCEPTED_FOR_IMPLEMENTATION（V6本机浏览器已由用户验证；V6.1补丁和目标托管需复验）

## 为什么改变 V5
官方公开评分为工具应用30%、趣味25%、创新20%、完成度20%、传播5%，专家/玩家70%/30%。公开页强调玩家真实互动。[S01/S02]
V5将完整交互留在本地、公开版只读，且把数据库、版本并发、管理后台放在前面，不能最佳服务这次比赛。
本 ADR **取代 ADR-0001 的冻结范围和 V5 的服务端优先级**，不是全盘否定数据校验。

## 决定
1. 主交付：可匿名直接互动的样例网站＋真实运行视频＋项目报告。
2. 默认技术：Vue/TypeScript/Three.js UI；**module Web Worker + Pyodide 314.0.6 + 其内置 pydantic 2.12.5**跑同一 Python 核心。[S04/S05]
3. 浏览器场景草稿、撤销栈、单调 client_revision、输入hash仍保留；移除首版数据库CAS和持久化后端依赖。
4. 首版不做 SQLite/SQLAlchemy/UoW、账号、后台生成队列、积分预留账本、多人协作；不需要公网Python后端。
5. Lux3D 网页生成→本地校准→发布核准模型包为主路径。可选本地CLI生成，云端Key不进网页。
6. 挑战目标是固定教学目标集合，不是把全部未知项勾成“安全”。剩余已触发、未知、未覆盖均须展示。
7. 现有 ReleaseVerifier 和导出安全工具仅作为**本地打包检查**保留，不进入浏览器bundle，不再扩建。
8. 先在真实浏览器和魔搭托管完成探针，不把 Node 成功当浏览器成功。

## 技术失败退出门
11/04–11/05先做浏览器探针；记录冷启动、依赖下载、3样例一致性、iframe/module worker/MIME。
工程目标（不是官方要求）：第一可操作界面≤3秒，规则就绪冷启动≤12秒，热评估p95≤150ms。
优先同源部署最小运行时与所需wheel，预热和资源渐进加载。目标失败要优化、明确降级提示。
若至11/06仍存在无法解决的浏览器/托管限制，改成**同一内核的无状态薄HTTP评估服务**，不加数据库、不重写TS规则；记录替代ADR与真实原因。不得退回只读展示而仍声称是交互Demo。

## 不变约束
不模拟真实事故；不制造安全分；不以视角高度推定实际可触及高度；不伪造生成和用户数据；未知不默认为否。
真实模型、浏览器和官网回执按实际来源记录；用户本地验证标USER_VERIFIED_RUN，本环境没跑不能冒称重测，尚未制作/提交保持NOT_RUN/NOT_SUBMITTED。
原用户所述Kiro/PUA全局配置未提供，不声称已同步；项目自行定义可检验的TDD与失败报告要求。
