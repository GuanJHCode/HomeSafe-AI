# 10｜接手、TDD、提交与失败报告
先读START_HERE、AGENTS、ADR-0002、00/01/07。V5历史文档不再作为活动架构。
首次确认Git工作区，不覆盖已有改动；当前包不执行git push。

## 开工指令
先复跑Python/契约/包检查与JS客户端测试，随后T01真实浏览器Pyodide与创空间风险探针。
通过后构建apps/web第一条3D互动；不要先开发SQLite、后台API、完整资产管理台或worker。
真实Lux3D小样与代码并行；缺模型时占位必须明确，不记作官方技术产物。
完成主线后才考虑本地收费CLI，不能自动生成或擅自充值。

## TDD
缺陷先写失败回归；运行并记录失败→最小修复→局部/全量测试。UI有E2E目标但不伪称执行了浏览器。
新规则先给触发/未触发/信息不足/不适用的例子；任何“目标成功”必须验证未清除其他未知。
不可用的网络、浏览器、SDK或真实账号测试标NOT_RUN，不写理论通过。
本包提供参考实现，接手Agent可重构但不得删反例保持绿灯。

## 提交
`feat: add role camera switch` / `fix: preserve unknown observations` / `test: reject stale replies`。任务ID写提交正文；type允许范围遵守本机全局8类原文，本包不自造列表。
一项任务一个清楚的变更集；不要强制每个微小改动都开分支，更不建设多Agent调度系统。
不同Agent不要同时改同一任务；最少协调字段是owner、task、branch、commit、状态、阻断项。

## 失败报告
写：期望/实际/复现命令/日志路径/排除假设/下一验证动作。
同一种失败两次没有新证据就停止盲改，缩小变量或使用已定义fallback，不擅自加新基础设施。
禁止隐藏失败、改测试标准迎合结果、删安全约束赶进度。
未取得用户Kiro全局规范或PUA配置原文；不安装不明插件、不虚构同步。若后续用户明确提供，先审查适用性及与本项目约束冲突。

## 交接
更新evidence/task-status.json和HANDOFF.md；不要填“完成”后留TODO。
提交材料绑定真实版本，口头“会继续”不是交付。官网授权由本人确认，不代接受法律条款。

用户V6真实浏览器验证见external-verification记录；本轮先复验部署补丁而非否定已有结果。官方字段按docs/11，不要求同一Demo字段双交。提交格式按AGENTS的<type>: <desc>。
