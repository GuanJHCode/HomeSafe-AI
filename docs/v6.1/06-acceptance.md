# 验收、赛事提交与维护

## 测试矩阵

| 范围 | 必查内容 | 可接受证据 |
| --- | --- | --- |
| 原生核心 | 规则、非法布局、未知、比较、挑战、异常 | V6.1 实际命令、环境与测试日志 |
| 契约 | canonical 模型生成；Schema/TS 一致 | 生成检查、严格类型检查 |
| 同源打包 | 官方无 version 的 lock、依赖闭包、hash、复制边界 | 真实分发检查＋反例测试 |
| Worker 客户端 | 乱序、超时、销毁、失败后重建、不重放旧动作 | JS 测试＋真实浏览器故障恢复 |
| 语义一致 | 原生与浏览器三样例、挑战输出 | 相同输入/hash 的语义 JSON 比较 |
| 3D 交互 | 合法/非法摆放、撤销、重置、切换视角 | 连续实录和至少三种合法布局 |
| 真资产 | 加载、校准、多实例、释放、来源 | 核准清单、hash、真实模型与记录 |
| 正式部署 | 匿名访问、另一网络、iframe、MIME、子路径 | 正式 URL、设备与时间记录 |
| 性能 | 冷启动、缓存后重载、热评估 | 网络/设备条件、样本量、p95；不能用单点代替 |
| 清单 | 输入/规则版本对应，已触发/未知/未覆盖保留 | 导出样本和当前场景比对 |

至少覆盖实际评审设备，规划 Chrome/Edge 与 Safari 的真实运行；缺少设备就记录未测。只有资源全部本地化后才测试并描述断网能力。静态站不能自动被称为离线应用。

## 提交材料

主项优先使用可匿名直接操作的在线 Demo。Demo 链接与视频按实际表单二选一；视频放报告、社媒或允许的补充区域，不能假定同一字段可同时上传。

报告包括：问题和受众、玩法、Lux3D 核心链、真实迭代、单一规则架构、双人群取舍、实际测试、试玩反馈、局限、授权、入口和维护。未做的试玩或生成就写未做。

视频建议约 3–4 分钟，至少一段连续真实操作：家具来源→双视角→调整引发冲突→再次调整→目标完成但问题保留→行动清单。等待可如实剪辑，不用生成画面冒充运行。

原材料安排小红书 #Aholo黑客松 传播；内容与真实成果一致，实际发布需执行并保留链接。本轮仅整理方案，不代发布、代报名或接受条款。
