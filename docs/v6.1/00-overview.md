# V6.1 总体方案

日期：2026-11-03（北京时间）。本文将 V6 浏览器优先设计与 V6.1 修订说明整理为当前实施基线；来源和验证等级见[来源记录](07-sources.md)。这里描述目标行为，不表示功能已实现。

## 产品与核心体验

安心屋帮助成年照护者在合成客厅中理解空间取舍。先看儿童视角的窗边支点，再看老人指定通道；移动家具后，系统解释哪些条件消失、哪些新条件出现、哪些资料仍未知。

一次完整体验应在约五分钟内完成：

1. 直接进入样例客厅，观察儿童和老人两种视角。
2. 点击检查卡，定位家具、窗口或通道以及判断依据。
3. 拖动/旋转允许的家具；非法摆放回弹并解释原因。
4. 对合法布局重算两类人群条件，比较变化，必要时撤销。
5. 达成本关目标后，同时显示仍已触发、待核查和未覆盖事项。
6. 导出包含布局版本、依据与局限的行动清单。

## 范围与优先级

| 优先级 | 内容 | 交付边界 |
| --- | --- | --- |
| P0 | 浏览器规则探针、匿名在线互动 | 需要正式托管与真实设备证据 |
| P0 | 合法布局、双视角、比较、撤销、挑战 | 单一内核，未知保留，不能通过改资料过关 |
| P0 | Lux3D 核心家具 | 先两件小样，最终以质量和预算决定规模 |
| P0 | 清单、报告、真实视频、提交与维护 | 内容和固定版本一致 |
| P1 | 更多布局、本地图生 3D、模型拆件动画 | 主线通过后才开展 |
| 暂不做 | 账号、数据库、多人协作、生成后台、积分账务平台 | 不成为首版依赖 |
| 不承诺 | 全屋扫描、完整人体导航、事故概率、安全认证 | 规则只检查已明确的教学条件 |

## 当前架构决策

采用 Vue 3 / TypeScript / Three.js 主线程，加 module Worker 中的 Pyodide 与同一 Python 核心。静态站发布已审核样例、模型和最小运行时。Lux3D 在本地制作资产，网页不持有密钥、不接收家庭照片、不创建付费任务。

如目标浏览器或托管限制无法解决，允许使用同一内核的无状态薄 HTTP 评估服务；记录阻断和替代决策，不重新膨胀为后端平台。

| 主题 | 当前决定 |
| --- | --- |
| V5 服务端产品思路 | 留在历史记录，首版不执行其持久化与后台优先级 |
| V6 浏览器优先 | 保留；在线互动为主交付 |
| V6.1 同源部署缺陷 | 按修订后的校验与打包逻辑验收，不能给官方 lock 人工补 version |
| 未知与挑战完成 | 目标达成与剩余问题并存，不输出全屋安全结论 |
| 赛事 Demo 字段 | 按当前表单选择链接或视频；主项优先在线链接 |
| 提交风格 | `<type>: <desc>`；任务 ID 放正文 |

## 信息边界

相机高度、人体能力参数与模型尺寸彼此独立；AI 预测尺寸只是待确认的校准候选。类别只能提供未确认 trait 候选，不能自动确认属性。未触发不等于安全，缺输入不等于未触发。样例与测试不能用于推断现实事故率。

## 开发价值排序

既有赛事材料记录的维度为技术应用 30%、趣味 25%、创新 20%、完成度 20%、传播 5%。本方案据此优先真实资产链、双人群取舍和可直接试玩的闭环；该比例作为材料记录，提交时仍核对实际表单。专家/玩家 70%/30%、Top50 阶段与 50 名玩家评委是不同概念，不能相互推导。
