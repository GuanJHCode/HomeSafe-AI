## 开工顺序

本轮完成的是方案梳理。下一步先恢复经过校验的 V6.1 参考包，再复跑检查；不能把当前文档仓库当作现成工程启动。T01 原生测试通过后继续真实浏览器和正式平台，不能拿 Node 或 localhost 结果替代。

T03 可以和代码开发独立进行，但真实收费任务需明确预算授权。先做两件完整小样再批量；不等待资产管理后台。

11/06 若关键运行时与托管兼容性仍阻断，按[部署退路](04-deployment.md)评估薄 HTTP 方案。功能冻结后只处理影响交付的缺陷。

## 任务完成定义

每项任务写明负责人、所用版本/提交、改动、实际命令、日志、验收结果和剩余限制。未运行标 NOT_RUN，受阻标 BLOCKED，未开始标 NOT_STARTED。既有测试记录不自动把本轮任务标 DONE。

机器可读状态见 [task-status.json](../../evidence/task-status.json)。任务由一位责任人维护，避免同时修改同一范围；不建设额外多 Agent 调度框架。

## 风险与处理

| 风险 | 处理 |
| --- | --- |
| 参考包不可取得或摘要不符 | 暂停代码导入；不拿 V6 冒充 V6.1 |
| 运行时加载慢或被平台限制 | 先同源最小依赖，再依据真实阻断考虑备用服务 |
| 真实模型质量或预算不足 | 减数量，保留真实核心资产和完整操作链 |
| 资料未知较多 | 对象级汇总并展示覆盖，不批量改成 false |
| 进度紧 | 保住一条完整互动、真实资产、报告与正式链接；裁 P1 |
| 网站/视频/报告版本不一致 | 冻结 release 与 hash，重新核验对应关系 |
