# 部署、V6.1 修订与故障退路

## 发布路径

本地构建正式前端，将含 index.html 的构建产物、核准 GLB、样例、最小运行时和核心包部署到静态托管。原方案优先魔搭创空间；在真正发布前验证平台的当前限制、子路径、iframe、module Worker、WASM MIME 和匿名访问。

参考版本固定为 Pyodide 314.0.6 / pydantic 2.12.5；这不是“当前最新版本”声明。初期可用固定 CDN 探针，正式方案优先同源最小集合。不把数百 MB 完整分发、无关字体或原始私有素材全部发布。

## 同源运行时的验收要求

运行文件包括 pyodide.mjs、pyodide.asm.mjs、pyodide.asm.wasm、python_stdlib.zip、pyodide-lock.json，加 pydantic 的 WASM wheel 依赖闭包。不能把本机 pip 的 pydantic_core wheel 塞给浏览器。

V6.1 修复了依赖 lock 中不存在的 info.version 的错误假设。恢复参考包后必须验证：

| 检查 | 正确行为 |
| --- | --- |
| 真实 lock 结构 | 无 info.version 仍可处理；不人工添加字段 |
| 运行时兼容性 | 校验 info.python=3.14.2、abi_version=2026_0、arch=wasm32；可选 package.json 版本 |
| 实际加载 | Worker 仍校验 py.version，不能仅依赖文件元数据 |
| 分发校验 | 可选 expected-lock-sha256 必须完整 64 位；保存实际摘要与元数据 |
| 真实性边界 | ABI 匹配只说明兼容性，不证明下载来源真实 |
| wheel | 必须完整 SHA，依赖闭包齐全，复制后再验 hash |
| 文件边界 | 拒绝规范化后重复名、符号链接、非空目标和被篡改文件 |
| 测试夹具 | 合成夹具明确标 synthetic；不能冒充官方原件 |

## 其余 V6.1 修订的验收

| 修订 | 验收方法 |
| --- | --- |
| 初始化失败 Promise 滞留 | 制造加载失败，恢复配置后重试；旧请求得到结束，新 Worker 可正常运行 |
| 重试污染 | 重建 Worker，清除失败模块/WASM/超时；不自动重放动作 |
| JSON 深嵌套 | 超过 64 层或递归异常返回 INPUT_TOO_DEEP；正常三样例语义不变 |
| 挑战成功摘要 | 目标达标仍展示已触发、待核查、未覆盖；缺计数不能视为零 |
| 类别注释 | 类别可提供未确认候选，不分派互斥规则，也不自动确认 traits |
| 源码导出 | 修改后重新审核清单，旧 manifest 不可继续冒充新文件摘要 |

修复代码现已导入并通过本机原生/JS 回归；真实 Pyodide 分发、浏览器和正式平台仍待单独复验，见[本次验证](../../evidence/IMPORT_VALIDATION_20261103.md)。

## 加载、缓存与性能

首屏显示加载阶段：运行时、依赖、规则、模型。优先椅子/柜体/窗口，其他资产渐进加载。错误不伪造绿色结果，明确显示重试。

沿用项目工程目标：首个可操作界面 ≤3 秒、规则冷启动 ≤12 秒、热评估 p95 ≤150 ms。目标需按设备与网络实测，不是平台或赛事承诺。V6 本机同源约 1.6 秒、CDN 约 10.4 秒仅属历史 localhost 测量，不能当公网指标。

核心、场景和资产都记录 hash；内容变化使用新版本地址。默认不加 service worker，避免评审使用旧缓存。依赖许可证随分发保留。

## 退出门

原计划 11/06 为技术路线检查点。若正式目标上的 Pyodide/静态托管仍有不可解决阻断，记录复现和替代 ADR，改用同一内核的无状态薄 HTTP 服务。保持输入校验、结构化错误、版本关联和匿名使用，不加数据库、不重写 TS 权威规则。只读视频不冒充互动站点。

## 公开内容和维护

禁止公开密钥、私人照片、账户截图、真实家庭档案或未核准模型。使用 Vue 插值/textContent，避免未经清洗的 HTML；GLB 外部资源 URI 需受控。

维护到 max(2026-12-31, 实际结果公布日+30天)，若官方要求更严格则延长。实际结果日未知时不安排关停。备用站点和视频用于故障恢复；正式入口变更按实际表单规则更新。
