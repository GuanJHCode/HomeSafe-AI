# Lux3D 核心资产工作流

## 主路径与交付物

先用 Lux3D 网页制作椅子与柜体各一件小样，下载 GLB，本地验证、校准与授权审核后放入正式场景。占位模型可用于开发，但不能计为真实 Lux3D 成果。

小样通过后按预算和质量扩展到约 6–10 件统一风格家具；这是项目目标，不是赛事数量门槛。房间、路线和高亮可程序生成，标为 procedural。

| 类别 | 每件资产的记录 |
| --- | --- |
| 来源 | 素材授权、生成记录、日期；没有 taskId 就留空 |
| 成本 | 质量选项、预计/实际扣分、失败尝试 |
| 文件 | 原件 hash、优化件 hash、版本、公开路径 |
| 校准 | 单位、朝向、底部原点、比例、bbox、人工确认、revision |
| 使用 | scene object、对应检查/挑战、导入前后截图 |
| 审核 | 公开授权、隐私、纹理与第三方许可证 |

验证纹理、旋转、选中、重载、多实例及资源释放，再检查面数、材质和加载性能。保留有意义的优化迭代，不为凑证据反复收费生成。

## 视觉与判断分离

替换 GLB 保持业务对象 ID 与规则关联。模型 bbox 和 ai_predict_size 只给待确认校准初值，不自动标为实测。校准改变计算依据时显式记录并重算，不杜撰供应商尺寸置信度字段。

## 可选本地 CLI

主线通过后才接入本地工具；网页、Worker、静态构建均无 Key。实际收费调用需明确授权并核对余额与素材权利。历史提到的 3300 积分不代表当前余额，也不假定会重复赠送。

创建前保存意图，成功立即保存任务 ID，之后只恢复/查询同一任务。创建超时可能已经受理，不自动重建，先核对任务和扣费。下载时效及 SDK 语义在真实接入时验证。

## 完成标准

两件小样完成生成→导入→校准→操作→规则反馈闭环；最终核心模型都有来源，网站、视频、报告对应同一版本。只有截图、占位或空来源模板不能通过资产门禁。
