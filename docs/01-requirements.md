# 需求、范围与产品约束

本文依据[用户提供的交接摘要](../materials/source/handoff-summary-20261103.txt)整理。这里描述的是目标行为，不代表已实现功能。

## 目标与人群

HomeSafe-AI 用三维房间、家具与明确规则帮助用户观察儿童及老人相关的空间问题，比较整改前后的变化，并导出可追溯的行动清单。结果应呈现依据和未知信息，不能宣称完成真实家庭安全鉴定。

## 首版演示闭环

1. 加载带有窗、椅子、柜体和老人指定通道的样例房间。
2. 窗边椅子触发相应空间关系检查，窗口防护信息未知时另列人工核查项。
3. 移开椅子、保存新场景版本并重新评估。
4. 椅子的新位置占用老人指定通道，产生另一类问题。
5. 再次调整位置并重新评估，比较前后结果。
6. 导出包含版本、检查依据、待核查项和局限的行动清单。

移走椅子不能使窗口防护等独立未知项自动消失，也不能据此宣布整个家庭安全。

## 核心功能边界

| 范围 | 要求 |
| --- | --- |
| 场景编辑 | 从模板创建、查看、移动对象、保存、撤销与重算 |
| 资产管理 | 导入 GLB、验证、校准、记录来源与人工批准 |
| 空间计算 | 考虑旋转后的家具占地、相交、距离及指定通道占用 |
| 双人群检查 | 同一场景可检查儿童与老人需求，并发现整改带来的冲突 |
| 可解释结果 | 显示对象、关系、输入依据、结果状态与需人工核查的原因 |
| 比较与报告 | 比较两个版本，解释差异，导出行动清单 |
| 可选增强 | 应用内 Lux3D 生成、预算预留与恢复、完整导航 |

## 三项必须保持的约束

**外观与计算数据分开。** 替换 Lux3D 视觉模型时保持对象编号、已确认尺寸、规则关联与历史记录。若校准改变实际计算依据，必须显式记录并重算。

**未知信息不能被当作安全。** 检查状态固定为 `triggered`、`needs_review`、`not_triggered`。缺少柜体固定情况等必要信息时应保留人工核查项。具体规则如何处理输入，待原规则契约补齐或另行定义。

**整改结果可以追溯。** 结果绑定场景版本、输入摘要与规则版本。旧请求晚到时不能覆盖新结果；对象从场景中删除，仅表示模型输入改变，不能自动记录为现实问题已解决。

## 不可超出证据的表述

- 首版称为“空间关系与指定通道占用检查”，不能将几何相交宣传为完整人体可达性分析。
- 参考代码测试通过不等于真实家庭安全有效性已验证。
- 真实 Lux3D 资产、完整应用、用户试用与最终参赛交付均需要独立证据。
- 当前摘要未给出八条规则的完整清单、阈值与依据；实现前必须补齐并评审。
