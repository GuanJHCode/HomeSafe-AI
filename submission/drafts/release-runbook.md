## 获准后部署与核对

托管必须按文件正确返回 JS、JSON、WASM MIME，支持 module Worker；静态子路径保留尾斜杠，入口与资源使用相对地址。不存在的资源返回 404，不能用 index.html 掩盖缺失 runtime。不要加入浏览器 API Key，不改变固定官方 lock，不新增 service worker 来掩盖网络缺陷。

1. 保存旧入口的 release 清单和可恢复构建。上传经核验的 `apps/web/dist/` 到获准目标，不混合两个版本。
2. 执行 `python scripts/check_deployment.py --url https://APPROVED-HOST/preview/ --dist apps/web/dist --output evidence/private/deployment-transport.json`，输出放在 dist 外；HTTPS URL 是示意参数，运行时替换真实获准目标。
3. 在同一目标用真实独立浏览器验证首次访问、刷新、子路径、iframe、Worker/WASM、拖动回弹、双视角、挑战、撤销、失败恢复和 JSON/打印；浏览器脚本见 START_HERE。记录浏览器/版本、设备、网络、时间、提交和实际 URL。
4. 在另一网络、真实 Edge 与 Safari 重复关键流程。无设备或网络条件则写 NOT_RUN。测量冷启动、缓存后重载、热评估 p95，记录样本数/统计方法，不以 CI localhost 替代。
5. 核对匿名访问、资源摘要、许可通知、无密钥或私人文件。HTTP 资源通过不等于交互通过，不把 transport 回执改成浏览器结果。

任一关键步骤失败，保留失败日志与截图，恢复上一个完整且权利有效的构建。先验证旧构建 CHECKSUMS，再回滚同一入口，再匿名验证。回滚不修复许可证缺失；没有可用旧版本时暂停入口并明确说明，不继续宣传“在线可玩”。回滚后报告和表单必须标识实际生效版本。
