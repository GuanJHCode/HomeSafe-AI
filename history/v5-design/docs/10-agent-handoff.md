# 10｜Codex / dots 持续接手与Git协作

这些是项目工作约定，不依赖某个产品的专属功能或未验证的连接能力。

## 每次会话开始

查看git status和当前branch，读AGENTS、task-status、最近commit和HANDOFF。不得清空别人未提交改动。运行基线或受影响测试，再从最小未完成任务继续。
没有实际远仓权限/网络时本地继续并如实记录，不凭本地commit宣称已push。用户负责Git上传时，不额外代为推送。

## 并行协作

一个任务一个owner和分支；不同agent使用独立checkout/worktree。契约由单一owner负责，合并后其他任务更新基线，不同时手改generated文件。
建议分工：A后端/规则、B前端/交互；资产制作由本人/授权流程；发布证据由单人汇总。小范围任务完成后再集成，不搞长时间互不兼容开发。

## 上下文保留

每次写 `evidence/HANDOFF.md`：当前任务、最新commit、文件、已运行测试、阻断、下一具体命令。task-status仅有NOT_STARTED/IN_PROGRESS/BLOCKED/DONE，只有实测完成才能DONE。
Git历史和仓库文件是长期状态源，不把聊天记忆当唯一项目文档。不可把API Key、私人照片、账户余额截图原件写进交接文本。

## 执行顺序

T00→T01→T02为第一段；T03真实资产可同步准备。先实现可运行交互，不重复扩展架构。出现新API变化或反例再写ADR并更新测试，不反复推倒重来。
运行时AI只负责开发辅助，不是应用组件；不要顺手添加模型聊天或调用订阅Key做线上服务。

## 每项输出

Task ID / commit / 实现类和方法 / 执行命令 / pass-fail-skip / 日志路径 / 未解决限制 / 下一项。例：“T01，SceneService.evaluate接通，接口单测X项通过；浏览器实测NOT_RUN”，不要写“已全面完成”。

## 首次可复制指令

见START_HERE.md。用户已经确定方向和技术栈，不再要求其重复确认；除收费、真实公开发布、协议等必要授权外，按任务推进。
